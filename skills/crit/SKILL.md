# crit — Codex 크로스모델 디자인·카피 비평

**목적.** Claude가 만든 UI는 Claude의 학습분포로 수렴한다 — **같은 모델은 자기 slop을 못 본다.** Codex(GPT)는 실측상 다른 디자인 편향을 가지므로(구조 경직성↓·지시 충실도↑), 스크린샷과 코드를 넘겨 **차가운 지적자(nitpicker)**로 쓴다. kickoff가 계획에 하는 일을 디자인에 한다.

**전제.** Codex CLI 로그인(`codex login status`). 스크린샷은 vcheck가 생성.

## 원칙
- **Codex 역할 = nitpicker, not assistant.** 칭찬 금지·결함만, 심각도 라벨 필수. "지지하지 말고 부숴라"를 프롬프트에 명시.
- **비전 환각 가드 (필수).** 비전 모델은 없는 UI 요소를 "봤다"고 보고할 수 있다(실측 정확도 60%대). Codex의 시각 지적은 **실행 전 Claude가 실제 코드/DOM에서 검증**하고, 검증 실패 지적은 `[미확인 — 기각]`으로 명시 폐기. **결정론 심판 = sloplint** — sloplint와 Codex가 충돌하면 sloplint가 이긴다.
- **No-echo.** Codex 지적을 wholesale 수용 금지 — 각 지적을 `수용/반박/기각` 처리하고 반박엔 근거 1줄. 종합에 "내가 뒤집은 것" 명시 (kickoff §no-echo와 동일 규율).
- **레퍼런스 없는 crit는 반쪽.** 디자인 의도(레퍼런스·토큰·anti-reference 선언)를 Codex에 함께 넘겨야 "의도적 선택"과 "기본값 수렴"을 구분해준다.

## 절차

### 0. 증거 수집
```bash
node ~/.claude/tools/headless/vcheck.mjs <url> <outdir>     # desktop.png + mobile.png
node ~/.claude/tools/headless/sloplint.mjs <url> --json     # 결정론 기준선 (비교용 선실행)
```
카피 검사도 겸하면: 페이지의 핵심 카피(히어로·CTA·섹션 제목)를 텍스트로 추출해둔다.

### 1. Codex 비평 (포그라운드 — 출력이 사용자에게 흐르게)
```bash
codex exec -s read-only -c 'tools.web_search=true' -c 'model_reasoning_effort="high"' \
  -i <outdir>/desktop.png -i <outdir>/mobile.png "$(cat <<'EOF'
You are an adversarial DESIGN nitpicker. Do not assist, do not praise — only defects.
This UI was generated by Claude, which converges to a known "AI slop" attractor. Your job:
find where this page is a default, not a decision.

Check against (1) the AI-slop tells: Inter/default fonts, lavender-purple, gradient glow,
center hero + badge above H1, 3-4 identical feature cards, colored left-border cards,
1-2-3 step sequences, stat banners, all-caps eyebrow labels, emoji icons, uniform radius;
(2) STRUCTURE: is the first viewport a working object or a generic pitch? would this layout
survive swapping the product name? (if yes → structural failure);
(3) COPY in the screenshots: AI-tone words (unlock/seamless/effortlessly/elevate,
"단순한 X가 아닙니다", "다양한", "혁신적인", mechanical 첫째/둘째/셋째), invented metrics;
(4) taste: hierarchy, spacing rhythm, typographic pairing — search the web for 2-3 real
reference sites in this product's genre and compare concretely.

DESIGN INTENT (judge "deliberate choice" vs "default convergence" against this):
<디자인 의도: 레퍼런스·토큰·anti-reference 선언 — 없으면 "no declared intent (그 자체가 지적 대상)">

For each finding: [SEVERITY: critical/high/medium/low] what / why it reads as AI-generated
/ concrete fix. You may only cite UI elements actually visible in the screenshots.
End with exactly one line: "VERDICT: APPROVED" or "VERDICT: REVISE".
EOF
)" < /dev/null
```
> `< /dev/null` 필수(stdin 무한대기 함정). 2라운드부터 `codex exec [플래그] resume <session-id>`로 같은 세션 이어서 "고쳐졌는지"를 검증시킨다(플래그는 resume **앞에**).

### 2. 판정·반영 (Claude)
1. Codex 지적 각각을 **실코드/DOM 검증** → `수용 / 반박(근거) / 기각(환각·미확인)` 표로 세션에 출력.
2. 수용분 수정 → sloplint 재실행(전후 점수 비교) → 필요 시 라운드 2 (**캡 3라운드**).
3. 카피 지적은 `references/copy-antipatterns.md` 목록과 대조해 이중 확인.

### 3. 아이덴티티 축적 (1분 — 이게 "나만의 디자인"이 쌓이는 지점)
crit에서 **사용자가 최종 채택/거부한 결정**을 프로젝트 `design.md`(있으면) 또는 DESIGNDNA repo의 anti-example 목록에 1-2줄 추가:
- 채택: "우리는 X 한다" (예: "히어로는 항상 실작동 객체")
- 거부: "우리는 Y 안 한다" (예: "카드 좌측 컬러보더 금지")
> 원리: **design 문서가 침묵하는 항목은 전부 모델 디폴트로 회귀한다** — crit 라운드마다 침묵 영역을 하나씩 명문화하면 그게 곧 디자인 아이덴티티다.

## 산출물
- 세션: Codex 비평 전문 + 수용/반박/기각 표 + sloplint 전후 점수 + "내가 뒤집은 것".
- 반영된 수정 커밋(사용자 승인 후) + design.md/anti-example 추가분.

## 안 하는 것
- Codex에 쓰기 권한 (read-only 고정 — 비평만).
- sloplint 없이 비전 판정만으로 재작업 결정 (환각 가드 위반).
- 3라운드 초과 핑퐁 · Codex 지적의 무검증 수용 (echo).
- 디자인 새로 짜기 (그건 hallmark/design-antislop 프로세스 — crit는 비평·교정만).
